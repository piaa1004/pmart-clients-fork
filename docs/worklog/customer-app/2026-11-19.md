## 카카오 로그인 실서버 연결(auth 0.4.0, ADR-0071)
- 사용자: "지금 로그인 기능 들어간것같은데 연결해주라".
- 백엔드 069dac2b auth 0.4.0: KAKAO·NAVER 도 Google 처럼 OIDC **ID 토큰**(JWT)을 providerToken 으로. 서버 설정(허용 aud) 없으면 422 CONFIG_REQUIRED. 백엔드 일지 기준 **LAN 배포 전·키 미설정**.
- `--only=auth` 다시 생성(contracts.lock). 생성 코드 변화 없음(enum 에 KAKAO·NAVER 이미 있음).
- 카카오: 앱은 이미 SDK `idToken` 을 보낸다 → 실서버 버튼에 카카오를 기본으로 켬(`serverLoginProviders`). 서버 설정 전이면 기존 처리대로 "준비 중" 문구.
- 네이버: 서버는 OIDC(인가 코드+PKCE, scope openid) `id_token` 을 받는데 flutter_naver_login 은 액세스 토큰만 준다 → 실서버에서는 숨김(`--dart-define=PMART_SOCIAL_NAVER=true` 일 때만). OIDC 라이브러리(예 flutter_appauth) 추가는 사용자 승인 필요.
- 검증: `flutter analyze` No issues, `flutter test` 552 통과(google_login_test 실서버 제공자 기대값 수정).

## 네이버 로그인 OIDC(인가 코드+PKCE)로 바꿈
- 사용자: "응 네이버 붙여줘" — 패키지 승인. `flutter_naver_login` 빼고 `flutter_appauth ^13.0.0`(pub.dev 최신, Flutter ≥3.44·Dart ^3.12 — 우리 3.47.5/3.13.4 맞음). 이유: 서버(auth 0.4.0)는 id_token 만 받는데 네이버 SDK 는 액세스 토큰만 준다.
- `NaverSocialTokenSource`: `authorizeAndExchangeCode`(nid.naver.com authorize·token, scope openid, secret 없음) → `idToken`. 취소 `FlutterAppAuthUserCancelledException` → null, 그 밖 PlatformException → 제공자 장애, Client ID 없음·idToken 없음 → 설정 문제.
- redirect `com.pmart.customer://oauth/naver`(build.gradle `appAuthRedirectScheme`). 매니페스트의 네이버 SDK meta-data(Client ID·Secret) 삭제 — 앱에 Secret 이 더 이상 들어가지 않는다. `.secrets/customer.env` 의 NAVER_CLIENT_SECRET 은 이제 안 씀.
- 실서버 버튼: 카카오·네이버·구글 모두.
- 남은 확인: 네이버 콘솔에 이 Callback URL 을 넣을 수 있는지(사용자), 백엔드 키 설정·LAN 배포, 실기기 로그인.
- 검증: analyze No issues, test 552 통과, LAN debug APK 빌드 성공(합친 매니페스트에 `RedirectUriReceiverActivity` scheme `com.pmart.customer`, 네이버 SDK meta-data 없음). 폰 연결 없어 설치 안 함.
- 이어서: 사용자 "그 url 안되는것같아서" — 네이버 콘솔이 `com.pmart.customer://oauth/naver` 를 받지 않음. BR-66 요청서 `docs/handoff/customer-app/2026-11-19-backend-naver-oauth-callback-relay.md`(LAN 게이트웨이 공개 중계 경로 → 앱 주소 302, 고정 목적지·저장/기록 없음, 콘솔 주소·사설 CA 확인). backend-requests·handoff README·안내 문서 갱신. 앱 코드는 회신 뒤 redirectUrl 만 바꾼다.
