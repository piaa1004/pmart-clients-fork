## 지급 관리·소명·이의 (백엔드 #210·#211 병합·LAN 배포 — 사용자 "병합 했어")
- 생성: `npm run gen:api -w web/rider-backoffice`(백엔드 main 6bf69d04 — execution 0.29.0·rider 0.15.0), contracts.lock 되돌림.
- 지급 관리(`/payouts`, 수행료 묶음): 지급 예정일(비우면 서버 오늘)·상태·라이더로 거르기, 표(라이더 RiderName·예정일·건수·합계·상태·마지막 표시). 결과 표시는 관리자만(PAYING·PAID·FAILED, FAILED 는 사유 필수, 회계 처리 번호 선택). 422 PAYOUT_NOT_DUE·409 는 서버 문구로.
- 소명·이의(`/appeals`, 지원센터 묶음): 상태(기본 결정 대기)·종류·라이더 거르기, 카드(종류·라이더·대상 배송/신청 당시 제한·라이더가 쓴 내용). 유지·인정 + 결정 메모(라이더에게 보임). 수행료 이의 인정 → 응답 adjustmentRequired 면 "이 배송 수행료 조정하기"(`/adjustments?deliveryId=`) — 조정 화면은 그 배송만 보이고, 조정 대기 목록에 없으면 숨기지 않고 이유를 알림.
- 결정·표시가 끝나면 그 줄이 목록에서 빠지거나(결정 대기) 입력 칸이 없어져(지급 완료) 줄 안 알림이 사라졌다 — 시험에서 발견, 결과 알림을 화면 위에 남기도록 고침.
- 조치 이력 코드 4개(PAYOUT_PAYING·PAYOUT_PAID·PAYOUT_FAILED·APPEAL_DECIDED), 오류 문구 PAYOUT_NOT_DUE·APPEAL_EXISTS.
- 열린 점: 수행료 조정(`/rider-earnings/{id}/adjustments`)은 산정 불가만 한 번 — 이미 산정·조정된 수행료나 추가 배달료 반려 건 이의를 인정해도 금액을 바꿀 API 가 없음(백엔드에 물음).

## 화면 번호 전수 정리 (ADR-0070 — 사용자 "이런거 들어가면 세부사항에서 볼 수 있게 하고 겉에선 다 정돈된 걸로 직관적이게 … 왜 아직 그대로야?")

## 접수 건 "처리 끝내기" — 도움요청 마무리 버튼
- 사용자: "도움요청 처리 완료는 지원센터에 상담사가 마무리해야 하는데 백오피스에 처리 완료 버튼이 없네".
- 원인: 도움요청에 접수 건(case)이 붙으면 서버가 도움요청 화면의 닫기를 막는다(409 HELP_REQUEST_HAS_CASE — 접수 건에서 닫기). 그런데 접수 건 화면이 1차(2026-11-17)에 보기만이라 닫을 곳이 없었다.
- 고침: 접수 건 상세에 "처리 끝내기"(case `POST /cases/{caseId}/closures` — 결과 5종·처리 내용, Idempotency-Key·X-Source-System·있으면 X-Expected-Version). 닫으면 서버가 붙은 도움요청도 RESOLVED. 닫힌 건엔 칸 없음, 성공은 화면 위 안내, 409 OPEN_OBLIGATIONS·403 은 이유를 보임. 도움요청 화면 안내 문구도 "접수 건의 처리 끝내기로" 로.
- 목: caseHandlers 에 closures(닫힌 건 표·시험마다 초기화, CASE-DF-1 은 OPEN_OBLIGATIONS 흉내).
- 검증: typecheck·lint 깨끗, test 114 통과(처리 끝내기 2건, 기존 "보기만" 시험 갱신), build 성공. 실서버 확인 전.
- 사용자 "상담사가 상담 완료할 수 있게 하라니까 왜 접수건으로 넘어가냐": 도움요청 대화 화면 머리(배송 상세 옆)에 **상담 완료** 버튼 하나. 접수 건이 붙었으면 그 접수 건을 닫고(case closures — 서버가 도움요청도 처리 끝), 없으면 도움요청을 직접 닫는다. 결과(기본 해결)·처리 내용(선택 — 비우면 "상담 완료 — 해결"). 접수 건 화면으로 넘어가는 링크·왼쪽 "처리" 칸·탭은 뺐다. 목 브라우저(PC5)에서 확인 — 머리에 버튼, 확인 창, "상담을 완료했어요 · 오후 5:46". test 114 통과.
